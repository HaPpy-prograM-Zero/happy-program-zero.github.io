Claude Code en los IDE de JetBrains: plugin, atajos y arreglos

Si trabajas en IntelliJ IDEA, PyCharm, WebStorm, GoLand, PhpStorm o Android Studio, un plugin conecta Claude Code con el IDE: los cambios se abren en el visor de diferencias del propio IDE, tu selección se comparte sola y Claude puede ver los marcadores de error del IDE. Aquí tienes cómo instalarlo y qué mirar cuando no conecta.

Instalar: dos piezas

El plugin no incluye Claude Code. Ejecuta el comando claude en el terminal integrado del IDE y se conecta a él, así que necesitas las dos cosas.

  • La CLI. Instala Claude Code si no lo has hecho (mira el índice de guías para lo básico). Si claude no está en el PATH, el plugin muestra el aviso «Cannot launch Claude Code».
  • El plugin. Instala el plugin de Claude Code desde el JetBrains Marketplace y reinicia el IDE. Si claude está en un sitio que el IDE no encuentra, pon la ruta completa en el ajuste Claude command del plugin.
  • El inicio de sesión funciona con una suscripción de pago de Claude o una cuenta de Console, y no hace falta clave de API. Te pide iniciar sesión la primera vez que ejecutas claude.

Usarlo

  • Dentro del IDE: ejecuta claude en el terminal integrado y todas las funciones de la integración quedan activas. El atajo para abrirlo es Ctrl+Esc (Cmd+Esc en Mac), o pulsa el botón de Claude Code.
  • Desde un terminal externo: arranca claude y escribe /ide. Confirma con un mensaje como «Connected to IntelliJ IDEA.» Arranca desde la misma carpeta que la raíz del proyecto si quieres que Claude vea los mismos archivos que el IDE.
  • Diferencias: los cambios se abren en el visor de diferencias del IDE en vez de en el terminal. En /config, el ajuste Diff tool alterna entre auto (IDE) y terminal. Según la documentación, tal como la leemos, esa opción solo aparece mientras Claude Code está conectado al IDE.
  • Selección y archivos: tu selección o pestaña actual se comparte con Claude, y Ctrl+Alt+K (Cmd+Option+K en Mac) inserta una referencia como @src/auth.ts#L1-99.
  • Diagnósticos: Claude puede leer los resultados de inspección del IDE (errores de lint y de sintaxis) cuando los pide. No los pide solo después de cada edición.

Es la misma idea que la extensión de VS Code, con una diferencia: aquí Claude Code se ejecuta en el terminal y el plugin conecta el IDE con él.

Ajustes que conviene conocer

Los ajustes del plugin están en Settings → Tools → Claude Code. Los que hacen falta: el Claude command (un comando propio o la ruta completa), una opción de macOS para usar Option+Enter como salto de línea en un prompt, y las actualizaciones automáticas del plugin. Quien use WSL pone en Claude command una orden que ejecute claude con wsl -d y el nombre de su distribución; la forma exacta está en la documentación.

Cuando algo no funciona

  • ESC no interrumpe a Claude: en Settings → Tools → Terminal, desmarca «Move focus to the editor with Escape» (o quita el atajo «Switch focus to Editor» en los atajos del terminal).
  • Faltan funciones: ejecuta Claude Code desde la raíz del proyecto, comprueba que el plugin está activado y reinicia el IDE por completo (la documentación dice que a veces hay que hacerlo más de una vez).
  • «No available IDEs detected» tras /ide: comprueba que el plugin está instalado y activado, reinicia el IDE y, si esperabas una conexión automática, comprueba que arrancaste claude desde el terminal del IDE.
  • «Command not found» al pulsar el icono: comprueba que claude --version funciona en un terminal normal y después pon la ruta del comando en los ajustes del plugin.
  • Desarrollo remoto (Remote Development): instala el plugin en el equipo remoto desde Settings → Plugin (Host), no en tu cliente local.
  • WSL2 no ve el IDE: la causa habitual es la red de WSL2 o el Firewall de Windows bloqueando el enlace entre WSL2 y el IDE en Windows. La documentación describe dos arreglos: una regla de firewall para la subred de WSL2 (un paso de administrador) o pasar WSL2 a red en modo espejo (Windows 11 22H2 o posterior). Sigue sus pasos exactos en vez de copiar comandos de un resumen.

Una nota de seguridad

Según la documentación, tal como la leemos, en modo acceptEdits Claude podría cambiar archivos de configuración del IDE que este puede ejecutar automáticamente, lo que permitiría saltarse los avisos de permiso de los comandos de shell. La documentación sugiere aprobar las ediciones a mano en un IDE de JetBrains, usar Claude solo con prompts de confianza y saber qué archivos puede modificar. Más sobre los modos en modos de permisos.

El plugin además abre una conexión local que la CLI usa para abrir diferencias, leer tu selección y pedir diagnósticos. Tu selección y el archivo abierto viajan a Claude con cada prompt; para dejar fuera un archivo sensible como .env, añade una regla de denegación Read para él (mira la guía de permisos). El ajuste «Accept connections from all network interfaces» hace que esa conexión sea alcanzable desde tu red local y el tráfico no va cifrado, así que déjalo apagado salvo que no haya otra opción.
