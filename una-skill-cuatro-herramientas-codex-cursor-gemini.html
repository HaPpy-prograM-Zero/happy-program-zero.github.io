Una carpeta de skill, cuatro herramientas: SKILL.md en Codex, Cursor y Gemini CLI

Una skill es una carpeta con un archivo SKILL.md dentro, y el formato es abierto: lo leen varias herramientas de programación. Una skill que escribiste o compraste para una herramienta suele poder usarse en otra sin cambios. Aquí tienes dónde busca cada una, cómo comprobar que cargó y qué suele fallar.

Qué pide el formato

El nombre de la carpeta va en minúsculas, números y guiones simples. Dentro está SKILL.md, que empieza con una cabecera corta que piden todas las herramientas: un name, que debe coincidir con el nombre de la carpeta, y una description que diga qué hace la skill y cuándo usarla. La especificación abierta de agentskills.io fija límites (un nombre de hasta 64 caracteres, una descripción de hasta 1.024) y recomienda que el cuerpo no pase de unas 500 líneas. Los scripts o las notas van en la misma carpeta.

Dónde busca cada herramienta

  • Claude Code: .claude/skills/ en el proyecto y ~/.claude/skills/ para todos tus proyectos.
  • Codex: .agents/skills/ en la carpeta desde la que lo ejecutas y en las carpetas superiores hasta la raíz del repositorio; ~/.agents/skills/ para todos tus proyectos; /etc/codex/skills/ para un administrador.
  • Cursor: .agents/skills/ y .cursor/skills/ en el proyecto; ~/.agents/skills/ y ~/.cursor/skills/ para todos tus proyectos. También lee .claude/skills/ y .codex/skills/, y esas mismas dos en tu carpeta personal.
  • Gemini CLI: .gemini/skills/ o el alias .agents/skills/ en el espacio de trabajo; ~/.gemini/skills/ o ~/.agents/skills/ para ti. Si existen las dos en el mismo sitio, gana .agents/skills/.

El atajo: una carpeta para tres herramientas

Codex, Cursor y Gemini CLI leen .agents/skills/ y ~/.agents/skills/, así que no necesitas tres copias. Claude Code mira en su propia carpeta: copia o enlaza las mismas carpetas de skills en .claude/skills/ si lo usas también.

mkdir -p ~/.agents/skills
cp -R mi-skill ~/.agents/skills/

Comprobar que cargó y llamarla

  • Codex: ejecuta /skills o escribe $ y el nombre de la skill. También puede elegir una por sí mismo cuando tu tarea encaja con la descripción. Si una skill nueva no aparece, reinicia Codex.
  • Cursor: abre Customize en la barra lateral y entra en Skills. En el chat del agente escribe / y elige la skill, o deja que decida el agente.
  • Gemini CLI: /skills list las muestra y /skills reload actualiza la lista después de copiar una carpeta. Cuando una tarea encaja, el modelo pide activar la skill y ves un aviso de consentimiento con su nombre y su carpeta.

Lo que suele fallar

  • El nombre debe coincidir con la carpeta. Lo dice la documentación de Cursor y también la especificación abierta.
  • El mismo nombre en dos sitios. Codex no fusiona skills con el mismo nombre, así que salen las dos en sus listas. En Gemini CLI la skill del espacio de trabajo gana a la del usuario. Cambia el nombre de una.
  • Evitar el uso automático. Codex tiene un agents/openai.yaml opcional donde policy.allow_implicit_invocation: false deja una skill solo para llamadas explícitas con $nombre. Cursor tiene disable-model-invocation: true en la cabecera de la skill.
  • Instalar desde un repositorio git en Gemini CLI: gemini skills install <url-git> --consent. La opción --consent se salta la confirmación de seguridad, así que úsala solo con un repositorio que hayas leído.
  • Los nombres y los planes cambian. La página de Google dice que Gemini CLI fue sustituido por Antigravity CLI el 18 de junio de 2026 para los usuarios del nivel gratuito y de Google One. Comprueba cuál tienes y lee su documentación.

Lee una skill antes de instalarla

Una skill son instrucciones que un agente sigue con tus permisos, y puede traer scripts. Abre el SKILL.md, mira cada archivo de la carpeta y desconfía de cualquier cosa que descargue y ejecute código. La skill gratis skill-check de nuestro repositorio de GitHub es una lista de comprobación de solo lectura para justo esto.
