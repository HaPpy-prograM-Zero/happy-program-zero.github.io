Claude Code en GitHub Actions: menciones @claude, instalación y costes

Con la GitHub Action de Claude Code puedes escribir @claude en el comentario de una issue o una pull request y hacer que Claude lea el código, haga un cambio y lo suba. También puede ejecutar un prompt con un horario o ante cualquier evento de GitHub. Aquí tienes cómo instalarla, cuánto cuesta, quién puede activarla y qué mirar cuando se queda callada.

Qué es (y qué no es)

Varios productos comparten el nombre Claude Code. Esta guía trata de la integración claude-code-action, que se configura con archivos de workflow en tu repositorio. Según la documentación, tal como la leemos, son cosas distintas: Code Review (revisión automática de cada pull request sin escribir un workflow), Claude Code en la nube (sesiones en máquinas de la nube) y el Agent SDK (automatización a medida fuera de GitHub Actions, sobre el que está construida esta action). GitLab tiene su propia página de CI/CD.

Instalarla

En cualquier caso necesitas acceso de administrador al repositorio.

  • Instalación rápida. En el repositorio, abre claude y ejecuta /install-github-app. Solo funciona con repositorios de github.com y espera que tengas la CLI de GitHub instalada y con sesión iniciada con gh auth login. Instala la app de GitHub de Claude, guarda tu credencial como secreto del repositorio, sube una rama con los archivos de workflow que elijas y abre una pull request. Fusiona esa pull request y @claude funciona. Si paras a medias con Esc, el mensaje final lista lo que ya se hizo.
  • Instalación manual. Instala la app de GitHub de Claude en el repositorio, añade tú el secreto y copia el claude.yml oficial de la carpeta de ejemplos de la action en .github/workflows/. La documentación lo llama un workflow que funciona, no solo un ejemplo. Usa este camino si no ejecutas Claude Code en local, si el comando falla o si quieres control total.

La credencial

  • Añade uno de dos secretos del repositorio: ANTHROPIC_API_KEY (una clave de API de la Claude Console) o CLAUDE_CODE_OAUTH_TOKEN (un token de tu suscripción de Claude en Pro, Max, Team o Enterprise, que se genera ejecutando claude setup-token en local).
  • En el workflow, pasa el secreto a la entrada que le corresponde: anthropic_api_key o claude_code_oauth_token.
  • Nunca subas una clave ni un token al repositorio. Guárdalo como GitHub Secret, referéncialo desde el workflow y dale solo los permisos que necesita.
  • Para un secreto compartido entre muchos repositorios, la documentación recomienda una clave de API mejor que un token OAuth, porque el token OAuth está ligado a la suscripción de quien lo generó.

Usarla

Comenta en una issue o pull request, por ejemplo @claude arregla el TypeError del componente del panel de usuario. Claude responde en un comentario y lo va actualizando mientras trabaja. También reacciona a un comentario de revisión, a una revisión de pull request, o al título o cuerpo de una issue recién abierta.

  • Modo interactivo: tu workflow no tiene entrada prompt, así que Claude espera la frase de activación, por defecto @claude.
  • Modo automático: tu workflow da un prompt, así que Claude se ejecuta sin esperar una mención, por ejemplo con un horario. Por defecto el resultado va al registro de ejecución del workflow y no a un comentario, salvo que el prompt le diga que publique y tenga forma de hacerlo.

Las reglas del proyecto, ponlas en CLAUDE.md en la raíz del repositorio: Claude las sigue al abrir pull requests (mira CLAUDE.md y memoria).

Quién puede activarla

  • Quien comenta necesita acceso de escritura al repositorio. Hay una entrada allowed_non_write_users para excepciones, que además requiere tu propio github_token. Los eventos sin autor humano, como un horario, se saltan esta comprobación.
  • Los bots se rechazan salvo que los pongas en allowed_bots, para evitar que unos bots activen a Claude en bucle. Una ejecución programada se atribuye a un usuario del repositorio, normalmente quien cambió por última vez la línea cron, así que si ese usuario es un bot, inclúyelo.

Cuánto cuesta

Cada ejecución usa dos cosas: minutos de GitHub Actions en el runner alojado, y tokens (o el uso de tu suscripción, si te autenticas con el token OAuth). La documentación sugiere formas de acotar los dos:

  • Escribe peticiones @claude concretas y usa plantillas de issues para dar el contexto desde el principio.
  • Mantén CLAUDE.md corto, porque se lee en cada ejecución.
  • Pon --max-turns en claude_args para limitar las iteraciones.
  • Usa tiempos máximos del workflow y los controles de concurrencia de GitHub para evitar trabajos descontrolados o en paralelo.

Cuando no responde

  • Sin respuesta a @claude: comprueba que la app está instalada en el repositorio, que los workflows están activados, que existe el secreto, que el comentario contiene @claude como palabra completa (no /claude ni @claude-bot) y que quien comenta tiene acceso de escritura.
  • Tu CI no se ejecuta con los commits de Claude: GitHub no lanza workflows para commits hechos con el GITHUB_TOKEN por defecto. Si le pasas ese token a la action, quítalo para que se autentique como la app de GitHub de Claude, y comprueba que los disparadores de tu CI incluyen los eventos que producen los pushes de Claude.
  • Errores de autenticación: prueba la clave o el token en local con claude antes de depurar el workflow.

Con un proveedor de nube, y desinstalar

Amazon Bedrock, Agent Platform de Google Cloud y Microsoft Foundry se admiten con entradas como use_bedrock, con federación OIDC en vez de una clave de API guardada. Para quitarlo todo: borra los archivos de workflow (claude.yml y, si lo elegiste, claude-code-review.yml), borra el secreto del repositorio y de los secretos de la organización, y desinstala la app de GitHub solo si ninguna otra función de Claude la usa. Borrar un secreto no revoca la credencial, así que retira también la clave de API en la Console.
