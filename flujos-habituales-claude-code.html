Flujos de trabajo de cada día con Claude Code

La mayoría de los días haces lo mismo: entender código, arreglar algo, cambiar algo, probarlo, entregarlo. Aquí tienes un conjunto corto de prompts y hábitos para cada cosa, con las opciones y atajos que ahorran tiempo. Cambia las palabras de los prompts como quieras; lo que importa es el patrón.

Entender un código

Empieza por lo general y ve afinando. Cada pregunta se apoya en la respuesta anterior.

dame una visión general de este código
explica los patrones de arquitectura principales
¿cómo se gestiona la autenticación?
busca los archivos del inicio de sesión y sigue un login desde la página hasta la base de datos

Usa las palabras de tu proyecto y pide un pequeño glosario de sus propios términos. Para ver cómo explora Claude por su cuenta, mira cómo funciona Claude Code.

Arreglar un fallo

Dale a Claude el comando que reproduce el problema y el error que muestra. Di si pasa siempre o solo a veces. Después pide opciones antes de tocar nada:

npm test falla con el error de abajo. Propón dos o tres causas posibles y cómo comprobarías cada una.
(luego) aplica la segunda solución y vuelve a ejecutar la prueba

Refactorizar en pasos pequeños

Pide el cambio y la comprobación a la vez, y mantén cada paso lo bastante pequeño para revisarlo.

busca llamadas a APIs obsoletas en este repositorio
refactoriza utils.js con sintaxis moderna manteniendo el comportamiento
ejecuta las pruebas de los archivos que has cambiado

Si un paso sale mal, rebobina hasta antes de él.

Escribir pruebas

¿qué funciones de este archivo no tienen pruebas?
añade pruebas siguiendo el estilo de las pruebas que ya existen
ahora añade casos límite: entrada vacía, extremos, errores
ejecuta las pruebas nuevas y arregla las que fallen

Claude lee tus pruebas actuales y sigue su marco y su estilo, así que señálale un buen ejemplo. Sé concreto sobre qué comportamiento hay que comprobar.

Abrir un pull request

Puedes pedirlo directamente («crea un pr») o ir paso a paso: resume el cambio, crea el PR y pide una descripción mejor. Lee el resultado antes de enviarlo y pide a Claude que señale riesgos. Tal como lo leemos, Claude Code enlaza la sesión con el pull request cuando Claude lo crea con gh pr create (o glab mr create en GitLab), y claude --from-pr 1234, con tu propio número, abre el selector de sesiones filtrado por las ligadas a ese PR.

Documentación, imágenes y notas

  • Documentación: pregunta qué funciones no tienen comentarios, nombra el estilo que quieres (JSDoc, docstrings) y pide ejemplos y una comprobación con las normas de tu proyecto.
  • Imágenes: arrastra una imagen a la ventana, pégala con Ctrl+V (Alt+V en Windows y WSL) o dale una ruta de archivo. Sirve para la captura de un error, una maqueta de diseño o un diagrama.
  • No solo código: Claude Code funciona en cualquier carpeta. Ejecútalo en una carpeta de notas o en un montón de archivos markdown para buscarlos y reorganizarlos.

Señalar archivos con @

Escribe @ y una ruta para incluir un archivo o una carpeta sin esperar a que Claude vaya a leerlos: explica la lógica de @src/utils/auth.js. Un archivo se incluye si cabe en el límite de lectura (un archivo de texto de más de 256 KB no); una carpeta da un listado, no el contenido. Además trae los CLAUDE.md del directorio de ese archivo y de sus padres. Con los recursos MCP funciona igual, como @servidor:recurso.

Una precaución: como una referencia con @ no hace ninguna llamada a una herramienta, tus hooks PreToolUse no se ejecutan para ella. Si usas hooks para controlar lo que Claude puede leer, añade también una regla de denegación Read para esas rutas (mira los permisos para empezar y la guía de hooks). La documentación describe además una variable de entorno, CLAUDE_CODE_DISABLE_FILE_MENTIONS, que impide que las referencias con @ incluyan contenido; pide una versión reciente.

Retomar mañana

claude --continue     # la sesión más reciente de esta carpeta
claude --resume       # elegir de una lista (o /resume dentro de una sesión)

Si no hay nada que continuar, Claude Code lo dice y sale. Para empezar de cero con un resumen, mira la nota de relevo.

Planificar primero, editar después

Si quieres revisar el plan antes de que se toque nada del disco, usa el modo plan: arranca con claude --permission-mode plan o pulsa Shift+Tab en una sesión hasta que la barra de estado muestre el modo plan. Claude lee y propone; edita cuando tú apruebas. Más en los modos de permisos.

Mantén limpio el chat principal

Leer muchos archivos llena el contexto. Encarga la exploración a un ayudante: usa un subagente para investigar cómo se renueva el token en nuestro código de autenticación. Lee en su propia ventana y te devuelve un resumen. Mira escribir un subagente.

Dos sesiones a la vez

claude --worktree feature-auth abre una sesión en su propia copia de trabajo y en su propia rama; ejecútalo con otro nombre en una segunda terminal para tener una paralela. El repositorio necesita antes al menos un commit. Mira los worktrees.

Úsalo en una cadena de comandos

git log --oneline -20 | claude -p "resume estos commits recientes"

La opción -p se ejecuta una vez e imprime el resultado, así que encaja en scripts, hooks y CI. Más en ejecutar Claude Code desde un script.

Ejecutarlo con horario

La documentación lista cuatro sitios donde puede vivir una tarea recurrente:

  • Tareas programadas en la nube: se ejecutan aunque tu ordenador esté apagado y también pueden empezar con una llamada a una API o un evento de GitHub.
  • Tareas programadas de escritorio: corren en tu máquina, así que pueden tocar archivos locales y cambios sin confirmar.
  • GitHub Actions: para trabajos ligados a eventos del repositorio o a un cron que vive junto a la configuración de tu flujo.
  • /loop: sondeo rápido mientras una sesión de la CLI sigue abierta.

Una tarea programada no puede hacerte preguntas, así que escribe el prompt como un encargo: qué es éxito y qué hacer con el resultado.
