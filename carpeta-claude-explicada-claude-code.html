La carpeta .claude explicada y lo que guarda Claude Code

Claude Code lee sus instrucciones, ajustes, skills, subagentes y memoria de dos sitios: una carpeta .claude en tu proyecto y otra .claude en tu carpeta personal. También escribe archivos ahí mientras trabajas. Saber cuál es cuál te dice qué editar, qué subir a git y qué limpiar.

Dos carpetas, dos trabajos

  • En tu proyecto: configuración compartida. Súbela a git y tu equipo también la tiene.
  • En tu carpeta personal (~/.claude): tu configuración personal, para todos los proyectos. En Windows es %USERPROFILE%\.claude.

La mayoría solo edita CLAUDE.md y settings.json. Lo demás es opcional: añádelo cuando lo necesites. Si tu repositorio ya tiene un AGENTS.md escrito para otros agentes de programación, Claude Code puede leerlo en lugar de un CLAUDE.md.

Los archivos que escribes tú

  • CLAUDE.mdInstrucciones que se cargan en cada sesión. De proyecto o globales. Sube a git el del proyecto.
  • CLAUDE.local.mdTus preferencias privadas para un proyecto, que se cargan junto a CLAUDE.md. Lo creas tú y lo añades a .gitignore.
  • rules/*.mdInstrucciones repartidas por tema, que opcionalmente se limitan a ciertas rutas.
  • settings.jsonPermisos, hooks, variables de entorno y valores de modelo por defecto. Sube a git el del proyecto.
  • settings.local.jsonTus cambios personales para un proyecto. No está pensado para git.
  • .mcp.jsonServidores MCP compartidos con el equipo. Solo de proyecto. Está en la raíz del proyecto, no dentro de .claude.
  • skills/<nombre>/SKILL.mdInstrucciones reutilizables que llamas con /nombre o que Claude recoge por su cuenta.
  • commands/*.mdPeticiones de un solo archivo. Mismo mecanismo que las skills.
  • agents/*.mdSubagentes, cada uno con su propia instrucción y herramientas.
  • output-styles/*.mdConjuntos de instrucciones que cambian cómo responde Claude.
  • ~/.claude.jsonEstado de la app, datos de la cuenta y servidores MCP personales. Solo global. No va a git.
  • keybindings.jsonTus atajos de teclado. Solo global.

¿No sabes dónde va un cambio? Permitir o bloquear una herramienta: permisos de settings.json o un hook. Ejecutar un script alrededor de las llamadas a herramientas: un hook. Mantener tus cambios personales fuera de git: settings.local.json. Una instrucción que llamas con /nombre: una skill. Los ajustes de archivos distintos pueden chocar, así que mira qué archivo de ajustes manda. Para elegir entre instrucciones, skills y hooks, mira CLAUDE.md, skill, hook o subagente.

Lo que escribe Claude Code mientras trabajas

Además de lo que escribes tú, ~/.claude se llena de archivos que crea Claude Code:

  • Transcripciones en projects/<proyecto>/: los mensajes, las llamadas a herramientas y sus resultados de cada sesión, más la instrucción del sistema, las definiciones de herramientas y los archivos de instrucciones que cargó.
  • Copias en file-history/: copias de los archivos antes de que Claude los editara, que usa /rewind. Cubren los 100 puntos de control más recientes.
  • Planes del modo plan, pegados grandes, registros de depuración (solo mientras esté activada la depuración) y otros archivos de trabajo.
  • Historial de peticiones en history.jsonl: lo que escribiste, con fecha y hora y la ruta del proyecto.
  • Memoria automática en projects/<proyecto>/memory/: las notas que Claude se deja a sí mismo entre sesiones.

Lo que hay que leer dos veces: es texto plano

La documentación dice que las transcripciones y el historial no están cifrados en el disco, y que los permisos de archivo de tu ordenador son la única protección. Si una herramienta lee un archivo .env o un comando imprime una credencial, ese valor se escribe en la transcripción de la sesión. Conviene pensar quién puede leer esa carpeta y qué copias de seguridad la incluyen.

Cuánto duran las cosas

  • La mayoría de los archivos de trabajo (transcripciones, copias, planes, registros de depuración, pegados) se borran solos cuando pasan de cleanupPeriodDays. Por defecto son 30 días, y el mínimo es 1. Poner 0 se rechaza.
  • Algunos archivos se quedan hasta que los borres tú, entre ellos history.jsonl y la caché de estadísticas de uso.
  • Los archivos de memoria automática no los barre esa limpieza.
  • Ejecutar claude -p con --bare se salta la limpieza por antigüedad en esa sesión.

Reducir lo que se guarda

  • Baja cleanupPeriodDays para conservar las transcripciones menos días.
  • Pon la variable de entorno CLAUDE_CODE_SKIP_PROMPT_HISTORY para que no se escriban transcripciones ni historial. En ejecuciones no interactivas, --no-session-persistence junto a -p hace lo mismo. Mira ejecuta Claude Code desde un script.
  • Deniega la lectura de archivos de credenciales con una regla de permisos. Mira una lista de partida de reglas de permisos.
  • Para borrar lo que Claude Code guarda de un proyecto, usa claude purge. Borra las transcripciones, la memoria automática, las entradas de tareas, depuración y copias por sesión de ese proyecto, las líneas correspondientes del historial y la entrada del proyecto en ~/.claude.json. Muestra el plan completo y te pide confirmar antes, y --dry-run enseña el plan sin borrar nada. Las versiones antiguas lo llamaban claude project purge.

Esto no lo borres

Las cachés y los archivos de bloqueo se pueden quitar sin problema. Conserva .credentials.json (tu inicio de sesión), agent-memory/ (memoria de subagentes) y las carpetas jobs/ y daemon/ (estado de las sesiones en segundo plano).

Pruébalo con algo inofensivo

  1. Abre tu carpeta ~/.claude y mira los nombres. No abras nada que no quieras tener en pantalla.
  2. Busca settings.json en la carpeta .claude de un proyecto y comprueba si está subido a git.
  3. Ejecuta claude purge <ruta de un proyecto de pruebas> --dry-run y lee el plan. No borra nada.
