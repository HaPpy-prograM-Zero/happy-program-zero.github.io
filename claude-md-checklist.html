A CLAUDE.md checklist: 10 checks before you trust your setup

CLAUDE.md is the file Claude Code reads at the start of every session to learn how your project works. A weak one is easy to write and hard to notice. Use these ten checks.

Based on our own daily use and on Anthropic's official page about memory, code.claude.com/docs/en/memory. Check that page for the current details.

  1. Is it short?

    Anthropic's guidance is to aim for under 200 lines per file. Longer files use more context and make it less likely that each rule is followed. If a rule matters for only one folder, move it into a path-scoped rule instead of the main file.

  2. Can every rule be checked?

    "Run npm test before committing" can be verified. "Test your changes" cannot. Rewrite each vague line until you could tell, from the result, whether it was followed.

  3. Are the commands real?

    Copy build, test and lint commands from your README or CI, then run each once. A wrong command in CLAUDE.md is followed faithfully.

  4. Do any rules contradict each other?

    If two instructions conflict, Claude may pick one arbitrarily. Search the file for "always" and "never" and read those lines side by side.

  5. Is there a map of where things live?

    One line per important folder ("API handlers live in src/api/handlers/") saves the assistant from guessing and saves you tokens.

  6. Does it say what not to touch, and is that enforced elsewhere?

    CLAUDE.md is context, not enforced configuration. It asks; it does not block. For something that must never happen, use permissions or a hook, not only a sentence in this file.

  7. Is it free of secrets?

    It is plain text and often committed to the repository. No keys, tokens, passwords or personal data, ever. Point to where the secret is kept instead.

  8. Is it organised?

    Group related rules under short headers and bullets. Organised sections are easier to follow than dense paragraphs.

  9. Do you know what was actually loaded?

    Run /context in a session and look at the list under Memory files. If a file you expected is missing, that is your first clue.

  10. When did you last review it?

    A stale rule is worse than none. Put a monthly reminder in your calendar, and delete a line each time you add one.
