Modo pantalla completa de Claude Code: parpadeo, scroll y copiar

Si la pantalla parpadea mientras Claude trabaja, la posición de scroll salta arriba del todo o una conversación muy larga pone lenta tu terminal, el renderizado en pantalla completa es el ajuste pensado justo para eso. También cambia cómo buscas, haces scroll y copias, y por eso sorprende. Aquí tienes qué hace y cómo activarlo o quitarlo.

Qué es

Según la documentación, tal como la leemos, el renderizado en pantalla completa dibuja Claude Code en la pantalla alternativa de la terminal, como hacen vim o htop, y solo pinta los mensajes que se ven. Eso reduce el parpadeo, mantiene la memoria estable en conversaciones largas y añade soporte de ratón. La caja de entrada se queda fija abajo. Si no se mueve mientras Claude trabaja, estás en pantalla completa. El nombre no tiene que ver con maximizar la ventana.

La documentación lo llama vista previa de investigación, así que los detalles pueden cambiar. Ayuda más en las terminales donde la velocidad de dibujo es el cuello de botella, como la terminal de VS Code, tmux e iTerm2.

Activarlo o quitarlo

  • /tui fullscreen relanza en pantalla completa con tu conversación intacta y guarda la elección.
  • /tui default vuelve al renderizado clásico.
  • /tui a secas te dice cuál está activo y, si un arranque fallido te mandó al clásico, por qué.
  • Para un solo arranque, pon CLAUDE_CODE_NO_FLICKER=1 antes de claude. Para forzar el clásico diga lo que diga el ajuste guardado, pon CLAUDE_CODE_DISABLE_ALTERNATE_SCREEN=1.
CLAUDE_CODE_NO_FLICKER=1 claude

En cuál empiezas depende de tu configuración y puede variar entre equipos, así que ejecuta /tui para verlo en vez de suponerlo. Algunas sesiones no pueden cambiar, por ejemplo si usas opciones de arranque que no se pueden trasladar; Claude Code imprime Cannot switch renderers in this session y no cambia nada.

Qué cambia al usarlo

  • Buscar. El Cmd+F de tu terminal y la búsqueda de tmux ya no ven la conversación, porque no está en el scrollback normal. Pulsa Ctrl+O para el modo transcripción, luego / para buscar y n y N para saltar entre resultados.
  • Devolvérsela a tu terminal. En el modo transcripción, [ escribe toda la conversación en el scrollback propio de tu terminal, así que funcionan la búsqueda nativa y el modo copia de tmux. v la abre en tu $VISUAL o $EDITOR.
  • Copiar. Pinchar y arrastrar selecciona dentro de Claude Code y copia al portapapeles al soltar el ratón. Puedes desactivarlo con Copy on select en /config.
  • Enlaces. Mantén Cmd en macOS, o Ctrl en el resto, y pincha en una URL o ruta de archivo para abrirla.
  • Una vista más tranquila. /focus muestra solo tu último mensaje, un resumen de una línea de las llamadas a herramientas y la respuesta final. Vuelve a ejecutarlo para quitarlo.

Scroll

  • PgUp y PgDn mueven media pantalla. Ctrl+Home salta al principio y Ctrl+End al último mensaje.
  • En el teclado de un MacBook, mantén Fn con las flechas para obtener PgUp, PgDn, Home y End. La documentación dice que ahí el atajo de ir al final no llega a Claude Code por defecto, así que pincha el botón Jump to bottom, baja con el scroll o reasigna la acción scroll:bottom (mira personalizar los atajos).
  • Subir con el scroll pausa el seguimiento automático para que la salida nueva no te arrastre abajo. Quítalo del todo con Auto-scroll en /config.
  • ¿La rueda va muy lenta o muy rápida? Ajusta CLAUDE_CODE_SCROLL_SPEED (un número positivo hasta 20, con decimales), o ejecuta /scroll-speed y cámbialo en vivo.
  • Si la rueda no hace nada pero PgUp sí, puede que tu terminal no reenvíe los eventos de ratón. En iTerm2 es la opción Enable mouse reporting del perfil.

Conservar la selección de tu terminal

La captura del ratón es la queja más habitual, sobre todo por SSH o dentro de tmux, porque el modo copia de tmux y herramientas parecidas no ven una selección hecha dentro de Claude Code. Dos formas de esquivarlo:

  • Puntual: mantén una tecla modificadora mientras arrastras para que la selección la gestione tu terminal. Según la documentación, tal como la leemos, es Fn en Terminal.app, Option en iTerm2 y Shift en la mayoría de las demás. Claude Code muestra la tecla correcta en su ayuda en pantalla.
  • Siempre: CLAUDE_CODE_DISABLE_MOUSE=1 conserva el dibujo sin parpadeo y la memoria estable, pero renuncia a capturar el ratón. Pierdes colocar el cursor con un clic, expandir con un clic y la rueda dentro de Claude Code; PgUp y PgDn siguen funcionando. CLAUDE_CODE_DISABLE_MOUSE_CLICKS=1 conserva la rueda y desactiva solo los clics. Si pones las dos, gana CLAUDE_CODE_DISABLE_MOUSE.
CLAUDE_CODE_NO_FLICKER=1 CLAUDE_CODE_DISABLE_MOUSE=1 claude

tmux

  • Para el scroll con la rueda, activa el modo ratón de tmux: set -g mouse on en ~/.tmux.conf y recarga. PgUp y PgDn funcionan igual.
  • No lo uses con el modo de integración tmux -CC de iTerm2. La documentación dice que la rueda no hace nada ahí y que el doble clic puede corromper la terminal. tmux normal dentro de iTerm2 va bien.
  • Las versiones antiguas de tmux no tienen salida sincronizada, así que aún puedes ver algo de parpadeo. Actualiza tmux o ejecuta Claude Code en su propia pestaña fuera de tmux.

Cuando algo se ve mal

  • Pantalla revuelta o medio en blanco: pulsa Ctrl+L para redibujar. La conversación y lo que escribías se quedan.
  • Restos de texto viejo, sobre todo en Windows Terminal: algunas terminales manejan mal las actualizaciones parciales. Pon CLAUDE_CODE_ALT_SCREEN_FULL_REPAINT=1 para repintar todas las celdas en cada fotograma. En PowerShell: $env:CLAUDE_CODE_ALT_SCREEN_FULL_REPAINT = "1" y luego claude.
  • «Fullscreen renderer didn't finish starting last time»: una sesión en pantalla completa de este equipo se cayó pronto, así que Claude Code arrancó la siguiente en clásico. Tras fallos repetidos se queda en clásico hasta que actualices o ejecutes /tui fullscreen. /tui confirma que ese es el motivo.
  • Sigue mal: vuelve con /tui default y avísalo con /feedback, indicando tu terminal y su versión.
