Sesiones de Claude Code: reanudar, nombrar y ramificar una conversación

Cerrar el terminal no pierde tu conversación de Claude Code. Cada conversación es una sesión guardada, ligada a una carpeta de proyecto, y puedes reabrirla, ponerle un nombre que recuerdes o ramificarla para probar algo distinto sin perder la original. Aquí tienes la versión corta.

Volver a una conversación

  • claude --continue reabre la sesión más reciente de la carpeta actual.
  • claude --resume abre un selector para que elijas una.
  • claude --resume nombre reanuda una sesión por el nombre que le diste. Si el nombre coincide con más de una, sale el selector con el nombre ya escrito como búsqueda.
  • /resume cambia a otra sesión desde dentro de la que estás. /clear también conserva la conversación anterior, así que puedes volver a ella con /resume.
  • claude --from-pr 123 abre el selector filtrado a las sesiones ligadas a esa pull request.

Ponles nombre para encontrarlas

Si trabajas en varias tareas, un nombre vale más que recorrer una lista. Empieza con claude -n refactor-login, renombra durante la sesión con /rename refactor-login, o pulsa Ctrl+R sobre una sesión en el selector. Si nunca le pones nombre, Claude Code crea un título corto a partir de tu primer prompt, y ese título generado también sirve con --resume.

El selector

  • Las flechas se mueven, Enter reanuda, Espacio previsualiza y escribir busca. Incluso puedes pegar la URL de una pull request para encontrar la sesión que la creó.
  • Por defecto muestra las sesiones de la carpeta actual (y sus worktrees). Ctrl+W amplía a todos los worktrees del repositorio y Ctrl+A a todos los proyectos del equipo; Ctrl+B filtra a la rama de git actual.
  • Las sesiones creadas con claude -p, con el Agent SDK, o cuyo primer prompt fue /loop, no salen en el selector ni en --continue. Aun así puedes reanudar una pasándole su ID de sesión.

Qué recupera una sesión reanudada

Según la documentación, tal como la leemos, al reanudar se restaura la conversación (si se había compactado, sigues desde el resumen más lo que vino después), el modelo que usaba la sesión, un agente con el que la arrancaste, el modo de permisos en la mayoría de los casos y las tareas programadas que no hayan caducado. Una herramienta que seguía ejecutándose cuando terminó el proceso no se vuelve a ejecutar. No todo vuelve: si la sesión dependía de opciones como --mcp-config, --settings, --plugin-dir o de carpetas añadidas, pásalas otra vez, y las carpetas añadidas a mitad de sesión con /add-dir tampoco se restauran. Una sesión que terminó en modo plan vuelve en modo plan.

En algunos planes puede salir un aviso «Resume this conversation?» para una conversación larga tras una pausa. Estima cuánto de tu límite de uso consumiría solo la conversación guardada. Si tu siguiente tarea no la necesita, empieza una conversación nueva y deja la vieja para luego (mira gastar menos cuota).

Ramificar una conversación

Para probar otro enfoque sin perder el camino que llevabas, ejecuta /branch (con un nombre si quieres, por ejemplo /branch probar-streaming). Copia la conversación hasta ese punto en una sesión nueva y te cambia a ella, y la original queda intacta en el selector. Desde la línea de comandos, claude --continue --fork-session hace lo mismo en un proceso nuevo; los permisos «permitir en esta sesión» no pasan a ese proceso nuevo, así que vuelves a aprobarlos. Si reanudas la misma sesión en dos terminales sin ramificar, sus mensajes se mezclan en una sola transcripción, así que ramifica. Para deshacer código y conversación dentro de una sesión, mira deshacer con /rewind.

Dónde se guarda

  • Las transcripciones son archivos JSONL de texto plano dentro de tu carpeta de Claude, en una subcarpeta projects, uno por sesión. Por defecto se conservan 30 días, algo que cambia el ajuste cleanupPeriodDays.
  • El formato del archivo es interno y cambia entre versiones, así que no montes scripts leyéndolo. Para guardar una copia legible, usa /export; para alimentar un script, usa claude -p con salida JSON.
  • Tus conversaciones están en tu disco, así que trata las transcripciones como sensibles: pueden contener lo que tú o una herramienta imprimisteis. No las compartas sin revisarlas.

¿Limpiar, compactar o ramificar?

/clear empieza con el contexto vacío y guarda la sesión anterior. /compact sustituye el historial por un resumen y sigue en la misma sesión. /context muestra qué ocupa espacio (más en qué sobrevive a /compact). Para llevar trabajo entre sesiones a propósito, una nota de relevo corta funciona bien, y para trabajo en paralelo mira los worktrees de git.
