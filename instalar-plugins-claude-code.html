Instalar y gestionar plugins de Claude Code

Un plugin es un paquete que añade skills, agentes, hooks y servidores MCP a Claude Code de una sola vez. Viene de un marketplace, que es un catálogo de plugins. Esta página cubre cómo instalar uno, elegir quién lo recibe, mantenerlo actualizado y quitarlo, con las comprobaciones que conviene hacer antes.

Instalar un plugin

El marketplace oficial de Anthropic (claude-plugins-official) se añade solo la primera vez que abres una sesión interactiva de Claude Code. Como ejemplo, esto instala commit-commands, que añade comandos para hacer commits, subirlos y abrir pull requests:

/plugin install commit-commands@claude-plugins-official

En una sesión esto no instala de inmediato. Abre el panel /plugin en los detalles de ese plugin para que lo revises y elijas un alcance antes. Para explorar, ejecuta /plugin sin nombre: la pestaña Discover lista los plugins de tus marketplaces y puedes escribir para buscar.

El panel de detalles puede mostrar Will install (los comandos, agentes, skills, hooks y servidores que añade) y, para plugins del marketplace oficial, un Context cost con dos estimaciones de tokens: lo que el plugin añade a cada mensaje, y lo que añaden sus skills y agentes una vez cargados. Esas estimaciones aparecen cuando abres el plugin nombrando su marketplace, como arriba, pero no desde la lista Discover. Lee el panel antes de instalar. Un plugin puede ejecutar hooks y servidores MCP, así que trátalo como cualquier código que dejas correr en tu equipo; la documentación tiene una página aparte sobre seguridad y confianza de los plugins.

Elige un alcance

  • Usuario: lo tienes en todos los proyectos de este equipo. Se anota en enabledPlugins de ~/.claude/settings.json.
  • Proyecto: activado para todos los que trabajan en el repositorio. Se anota en .claude/settings.json, que subes al repositorio. Subirlo activa el plugin para tus colaboradores pero no lo descarga en sus equipos; cada uno ejecuta además una vez claude plugin install <nombre>@<marketplace> --scope project.
  • Local: lo tienes solo en este repositorio. Se anota en .claude/settings.local.json.

Mira qué archivo de ajustes manda si el mismo plugin está fijado en más de un sitio.

Comprueba que funcionó

La última línea del resumen de instalación dice si el plugin ya se puede usar: activo ya, activo pero un servidor incluido necesita configuración (usa Configure en la pestaña Installed), hace falta recargar (Claude Code normalmente ejecuta /reload-plugins por ti), o no se pudo cargar (abre la pestaña Errors de /plugin). Luego escribe / y busca las skills del plugin con la forma /<plugin>:<skill>, como /commit-commands:commit. claude plugin list en tu shell muestra versión, alcance y estado.

Desde tu shell

claude plugin install formatter@your-org --scope project

Esto instala sin abrir una sesión, por ejemplo desde un script de preparación. El alcance por defecto es usuario. Los plugins se cargan la próxima vez que abras Claude Code, o cuando ejecutes /reload-plugins en una sesión abierta. Algunos plugins se instalan ejecutando un comando que nombra su marketplace; Claude Code te lo muestra y te pide aceptarlo, y un script pasa --yes para aceptar.

Añadir un marketplace

Solo lo necesitas para plugins que no están en el marketplace oficial, como uno que publicó un compañero. Claude Code tiene que conocer un marketplace antes de que puedas instalar desde él:

/plugin marketplace add owner/repo
/plugin marketplace add owner/repo#v1.2.0
/plugin marketplace add https://example.com/marketplace.json
/plugin marketplace add ./my-marketplace

La fuente puede ser un repositorio de GitHub (añade #ref para fijar una rama o etiqueta), una URL de git, un directorio o archivo local (empieza una ruta relativa con ./, porque un simple nombre/nombre se lee como repositorio de GitHub) o un marketplace.json alojado. Incluye https:// en cada URL. Desde el shell, claude plugin marketplace add admite las mismas fuentes. Un marketplace es código en el que decides confiar, así que añade solo los que conozcas.

Gestionar lo instalado

  • La pestaña Installed de /plugin lista tus plugins. Espacio activa o desactiva el seleccionado, Enter abre sus detalles con Update now y Uninstall.
  • Desde el shell: claude plugin disable|enable|uninstall <nombre>@<marketplace>, con --scope para apuntar a un alcance.
  • Si desinstalas un plugin que activa el .claude/settings.json del repositorio, Claude Code pregunta si desactivarlo solo para ti (queda instalado para el proyecto) o desinstalarlo para todos.
  • Quitar un marketplace desinstala todos los plugins que instalaste de él.

Vigila lo que te cuesta

Los plugins añaden a tu contexto. claude plugin details <nombre> muestra los tokens que un plugin añade a cada sesión donde está activado y qué componente aporta más. En la pestaña Installed, los plugins que no has usado hace tiempo aparecen bajo un encabezado Not used recently, un buen sitio para desactivar o quitar lo que ya no necesitas. Mira gastar menos cuota y la ventana de contexto.

Actualizaciones

Los plugins se actualizan solos cuando su marketplace tiene la actualización automática activada. Según la documentación, viene activada por defecto en los marketplaces oficiales de Anthropic y en los añadidos desde claude.ai, y desactivada en todos los demás, incluidos el marketplace de la comunidad, los de terceros y los locales. Una sesión en marcha conserva las versiones que ya cargó; ves un aviso y ejecutas /reload-plugins para aplicar, o la siguiente sesión carga las versiones nuevas. Para actualizar un plugin ya, elige Update now o ejecuta claude plugin update <plugin>@<marketplace>. No hay ningún comando que actualice todos los plugins a la vez, pero en la pestaña Marketplaces puedes elegir Update marketplace para actualizar los plugins que instalaste de un marketplace.

Conviene saber

  • Una sesión en la nube no carga los plugins instalados en tu equipo, ni los que activan los ajustes de tu repositorio.
  • Los hooks de los plugins y los servidores MCP locales se ejecutan fuera del sandbox.
  • Si un plugin parece no hacer nada, mira depurar la configuración.

Para entender las piezas que agrupa un plugin, mira las skills, los hooks, los servidores MCP y los subagentes, y las buenas prácticas para saber cuándo usar cada una. Todas las guías están en el índice de guías.
